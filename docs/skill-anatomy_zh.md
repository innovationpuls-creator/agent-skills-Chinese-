# 技能结构规范

本文档描述了 agent-skills 技能文件的结构和格式。在贡献新技能或理解现有技能时，以此作为指南。

## 文件位置

每个技能都在 `skills/` 下的自己的目录中：

```
skills/
  skill-name/
    SKILL.md           # 必需：技能定义
    supporting-file.md # 可选：按需加载的参考资料
```

## SKILL.md 格式

### Frontmatter（必需）

```yaml
---
name: skill-name-with-hyphens
description: 引导代理完成[任务/工作流]。使用场景：[具体触发条件]。
---
```

**规则：**
- `name`：小写，连字符分隔。必须与目录名匹配。
- `description`：以第三人称描述技能功能，然后包含一个或多个清晰的"Use when"触发条件。要同时包含*是什么*和*何时使用*。最多 1024 个字符。

**为什么这很重要：** 代理通过阅读描述来发现技能。描述被注入到系统提示词中，所以它必须告诉代理技能提供什么以及何时激活。不要总结工作流 —— 如果描述包含流程步骤，代理可能会遵循摘要而不是阅读完整的技能。

### 标准章节（推荐模式）

```markdown
# 技能标题

## Overview
一两句话解释这个技能做什么以及为什么重要。

## When to Use
- 触发条件列表（症状、任务类型）
- 何时不使用（排除项）

## [Core Process / The Workflow / Steps]
主要工作流，分解为编号步骤或阶段。
在有帮助的地方包含代码示例。
在有决策点的地方使用流程图（ASCII）。

## [Specific Techniques / Patterns]
特定场景的详细指导。
代码示例、模板、配置。

## Common Rationalizations
| 自我合理化 | 现实 |
|---|---|
| 代理用来跳过步骤的借口 | 为什么这个借口是错误的 |

## Red Flags
- 表明技能被违反的行为模式
- 审查期间要观察的事项

## Verification
完成技能流程后，确认：
- [ ] 退出标准检查清单
- [ ] 证据要求
```

## 章节目的

### Overview
技能的"电梯演讲"。应该回答：这个技能做什么，为什么代理应该遵循它？

### When to Use
帮助代理和人类决定这个技能是否适用于当前任务。包括正向触发（"Use when X"）和负向排除（"NOT for Y"）。

### Core Process
技能的核心。这是代理遵循的分步工作流。必须具体且可操作 —— 不能是模糊的建议。

**好：** "运行 `npm test` 并验证所有测试通过"
**坏：** "确保测试能工作"

### Common Rationalizations
精心制作的技能最独特的特征。这些是代理用来跳过重要步骤的借口，配以反驳。它们防止代理通过自我合理化跳出流程。

想想每次代理说"我稍后添加测试"或"这足够简单可以跳过规格"的时候 —— 把这些放在这里，配以事实反驳。

### Red Flags
技能被违反的可观察迹象。在代码审查和自我监控期间有用。

### Verification
退出标准。代理用来确认技能流程完成的检查清单。每个复选框都应该可以用证据验证（测试输出、构建结果、截图等）。

## 支撑文件

仅在以下情况创建支撑文件：
- 参考资料超过 100 行（保持主 SKILL.md 聚焦）
- 需要代码工具或脚本
- 检查清单足够长以至于需要单独文件

当模式和建议在 50 行以下时，保持内联。

## 写作原则

1. **流程优于知识。** 技能是工作流，不是参考文档。步骤，而非事实。
2. **具体优于笼统。** "运行 `npm test`" 比"验证测试"更好。
3. **证据优于假设。** 每个验证复选框都需要证明。
4. **反自我合理化。** 每个值得跳过的步骤需要在合理化表格中有反驳论点。
5. **渐进式披露。** 主 SKILL.md 是入口点。支撑文件只在需要时加载。
6. **注意 token。** 每个章节都必须证明其存在的合理性。如果删除它不会改变代理行为，就删除它。

## 命名约定

- 技能目录：`lowercase-hyphen-separated`（小写连字符分隔）
- 技能文件：`SKILL.md`（始终大写）
- 支撑文件：`lowercase-hyphen-separated.md`（小写连字符分隔）
- 参考资料：存储在项目根目录的 `references/`，不在技能目录内

## 跨技能引用

按名称引用其他技能：

```markdown
按照 `test-driven-development` 技能编写测试。
如果构建中断，使用 `debugging-and-error-recovery` 技能。
```

不要在技能之间重复内容 —— 改为引用和链接。
